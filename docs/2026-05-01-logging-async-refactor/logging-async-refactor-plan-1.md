# Plan 1: 日志体系改造

## 前置依赖
- 无

## 本次目标
- 将后端代码中的 `print!`、`println!`、`eprint!`、`eprintln!` 全量替换为 `log` 宏。
- 建立统一日志级别映射规则，避免错误信息丢失或日志噪音。
- 保证日志初始化路径符合项目约束（`custom_utils::logger::logger_feature`）。

## 涉及文件
- `src-tauri/src/lib.rs`
- `src-tauri/src/main.rs`
- `src-tauri/Cargo.toml`（仅在需要补齐依赖特性时）

## 详细设计
- 替换策略：
  - 状态流转与生命周期日志：`info!`
  - 可疑但可恢复场景：`warn!`
  - 失败路径与返回错误前日志：`error!`
  - 排障细节（模型路径、资源探测）：`debug!`
- 日志边界：
  - 保持“单次错误单点记录”，避免上层再次重复打印同一错误。
  - 仅在边界层（命令入口、后台任务入口）记录错误；内部函数优先返回 `Result`。
- 初始化要求：
  - 在 `main` 或应用启动最早阶段初始化 logger。
  - 初始化失败时给出明确兜底行为（例如返回错误或单次 stderr 报错后终止）。

## 测试案例
- 正常路径：启动应用后关键流程（初始化、开始录音、停止录音）均有对应 `info` 日志。
- 边界条件：可选资源目录不存在时输出 `warn/debug`，不影响程序继续。
- 异常场景：模型构建失败、DB 初始化失败，输出 `error` 且错误向上返回。
