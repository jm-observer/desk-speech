# Plan 3: 前端展示与交互反馈设计

## 前置依赖
- Plan 1
- Plan 2

## 本次目标
- 让用户可感知“优化先完成、翻译后完成”的分阶段结果。
- 明确失败提示语与展示降级，避免因翻译失败造成整体不可用感知。

## 涉及文件
- `src/**/store*.ts`
- `src/**/types*.ts`
- `src/**/components/*.tsx`（包括 `SettingsModal.tsx` 设置界面改造）
- `src/**/api*.ts`

## 详细设计
- 展示层策略：
  - 第 1 行：原始文本（实时显示）。
  - 第 2 行：优化文本（优化成功后更新；失败则显示“优化失败”状态）。
  - 第 3 行：英文翻译（翻译成功后更新；失败则显示“翻译失败，已保留优化文本”）。
- 状态呈现：
  - `running` 显示轻量加载态（仅阶段级，不阻塞整体面板）。
  - `failed` 显示可读错误摘要（脱敏后）。
- 数据更新机制：
  - 前端按段落 id 合并增量事件，不整页刷新。
  - 仅当事件版本不低于当前版本时更新，防止乱序覆盖。
- 交互细节：
  - 复制按钮优先复制翻译文本；翻译缺失时退化复制优化文本。
  - 若仅有原始文本，复制原始文本并给出提示。
- **设置界面改造**（`SettingsModal.tsx`）：
  - 原有单个"系统提示词" textarea 拆分为两个独立 textarea：
    1. **优化提示词**（`optimize_prompt_template`）：标签"优化系统提示词"，placeholder 提示"用于文本润色、纠错、去口语噪音"。
    2. **翻译提示词**（`translate_prompt_template`）：标签"翻译系统提示词"，placeholder 提示"用于将优化后文本翻译为英文"。
  - 两个 textarea 上下排列，各自带有简短说明文字。
  - `patch()` 调用改为分别写入 `optimize_prompt_template` 和 `translate_prompt_template`。
  - 移除原 `prompt_template` 字段的 UI 引用。

## 测试案例
- 正常路径：先看到优化结果，再看到翻译结果，UI 顺序正确。
- 边界条件：仅优化成功，翻译失败，复制功能回退到优化文本。
- 异常场景：收到乱序事件时，不应覆盖较新状态。
- 可用性场景：网络抖动导致翻译延迟时，优化结果持续可见且可操作。
