# Tauri 麦克风识别低内存与词修正持久化设计

## 时间
- 创建时间：2026-04-29
- 最后更新：2026-04-29

## 项目现状
- 当前示例路径：`tauri-examples/non-streaming-speech-recognition-from-microphone`
- 录音数据全部保存在内存 `recorded_audio: Vec<f32>`，无容量上限
- 识别结果仅保存在内存 `segments: Vec<SegmentResult>`，退出进程即丢失
- 前端已有设置弹窗（VAD 参数），尚无“词修正”可视化配置
- 后端已支持同音词替换资源加载（`lexicon.txt` + `replace.fst`），但不支持运行时动态管理

## 整体目标
1. 将内存音频保留窗口限制为最近 10 分钟，避免超长录制导致内存线性增长。
2. 将识别文本持久化到 SQLite 数据库，支持会话级管理与历史查询。
3. 在前端新增“词修正”配置与展示能力，配置写入数据库并可动态加载生效。
4. 新增“每次识别出文字自动复制到剪贴板”能力，支持开关控制。

## 关键决策
- 数据库选型：`SQLite`（已确认）。
- 词修正策略：第一阶段仅实现“文本替换规则（source -> target）”，暂不实现 hotword boosting。
- 原因：
  - 文本替换规则可解释性强、可审计、可快速迭代；
  - 不依赖模型/解码器细节，跨模型行为更稳定；
  - hotword boosting 涉及模型适配和权重调参，放在后续二期。

## 风险与待定项
- 待定 1：10 分钟限制仅用于内存回放窗口，还是同时限制导出“Save all”范围（默认仅限制内存，不限制会话归档导出）。
- 风险 1：在录制线程内同步写库可能引入抖动，需要异步队列解耦。
- 风险 2：词修正规则热更新与当前识别流并发读写，需要版本快照避免竞态。
- 风险 3：自动复制频率过高可能影响体验，需要去重与节流策略。
- 风险 4：历史数据增长后查询性能下降，需要索引与分页策略。
