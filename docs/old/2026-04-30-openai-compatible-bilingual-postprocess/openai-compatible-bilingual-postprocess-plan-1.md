# Plan 1: 异步改造与执行骨架

## 前置依赖
- 无

## 本次目标
- 后端调用链先完成 async 化，消除阻塞点。
- 形成“主流程立即返回原始文本 + 异步任务处理 LLM”的执行骨架。

## 涉及文件
- `src-tauri/src/**/service*.rs`
- `src-tauri/src/**/repository*.rs`
- `src-tauri/src/**/pipeline*.rs`
- `src-tauri/src/lib.rs`

## 详细设计
- 主流程行为：
  - ASR 产出原始文本后立即进入既有后续流程并推送前端第 1 行。
  - 同步阶段不等待 LLM，避免用户感知延迟。
- 异步任务行为：
  - 为每条候选段落启动独立异步任务（可被 latest-only 逻辑淘汰）。
  - 任务完成后再触发二次推送（优化中文 + 英文）。
- 异步改造边界：
  - 仓储、服务、命令入口统一 async。
  - 禁止在 async 上下文执行阻塞 I/O。

## 测试案例
- 正常路径：原始文本先到达，异步结果后到达。
- 边界条件：高频段落输入下主流程延迟保持稳定。
- 异常场景：异步任务失败不影响主流程继续执行。
