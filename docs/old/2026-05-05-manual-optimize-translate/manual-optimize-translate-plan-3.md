# Plan 3: 前端按钮与刷新交互设计

## 前置依赖
- Plan 1: 手动后处理状态模型与接口契约
- Plan 2: 后端单条手动后处理编排设计

## 本次目标
- 在现有 `SegmentCard` 中增加单条手动触发入口，并与现有复制按钮、处理中状态和列表刷新机制协同工作。
- 保证用户能明确知道“哪一条在处理、何时不可点、失败后如何重试”。
- 维持当前界面风格，不引入新的复杂弹窗流程。

## 涉及文件
- `src/src/components/SegmentCard.tsx`
- `src/src/App.tsx`
- `src/src/api/tauri-client.ts`
- `src/src/store/useAppStore.ts`
- `src/src/components/ui/Button.tsx`

## 详细设计

### 1. 按钮位置与文案

按钮放在 `SegmentCard` 顶部右侧操作区，与“复制中文”“复制英文”并列，文案为：

- 默认：`手动优化与翻译`
- 处理中：`处理中...`

按钮不建议放在正文区域，理由：

- 与复制、导出同属“针对当前分段的动作”。
- 不打断文本阅读流。
- 现有 hover 操作区已经形成交互习惯，新增动作成本最低。

### 2. 组件接口调整

`SegmentCardProps` 建议新增：

```ts
onManualOptimizeTranslate: (segment: Segment) => void;
manualBusy?: boolean;
```

其中：

- `onManualOptimizeTranslate` 由 `App.tsx` 统一实现，避免卡片组件直接感知 Tauri。
- `manualBusy` 用于表示命令发起到结果刷新之间的前端局部忙碌态。

### 3. 禁用条件

按钮在以下任一条件满足时禁用：

1. `segment.revision` 不存在。
2. `segment.text_raw.trim()` 为空。
3. 当前记录已经处于处理中：
   - `optimize_status` 为 `pending` 或 `running`
   - 或 `translate_status` 为 `pending` 或 `running`
4. `manualBusy === true`
5. 可选：应用全局 `isBusy` 为真且团队希望串行化所有命令。

### 4. 点击流程

前端流程建议：

1. 用户点击按钮。
2. `App.tsx` 先将该 `revision` 加入 `manualBusyRevisions`。
3. 调用 `TauriAPI.manualOptimizeTranslate(revision)`。
4. 命令成功后，立即触发一次列表刷新：
   - 优先调用 `listSegments(0, 200)` 重新拉取。
   - 若录音仍在进行，也继续保持已有轮询，不额外关闭。
5. 命令失败时：
   - 打印错误日志。
   - 弹出轻量提示，文案如 `手动优化与翻译失败`。
6. 最终无论成功失败，都将该 `revision` 从 `manualBusyRevisions` 移除。

### 5. 刷新策略

本轮不新增事件总线，采用“局部乐观禁用 + 命令后刷新”的最小实现。

#### 非录音状态

- 命令结束后主动调用一次 `listSegments(0, 200)`。
- 更新后的数据库状态成为最终真相源。

#### 录音状态

- 命令结束后也可主动刷新一次数据库列表，保证历史数据同步。
- 同时保留 `getRecordingState` 的轮询，因为内存态还承载自动识别中的最新分段。

#### 合并原则

- 继续复用 `mergeSegmentsByRevision` / `getSegmentKey` 的合并逻辑。
- 若同一条记录来自数据库刷新和内存轮询，则以更高 `revision` 或更新后的状态覆盖旧对象。

### 6. 用户反馈

建议反馈层次如下：

1. 按钮本身：
   - 文案切换为 `处理中...`
   - 禁用点击
2. 卡片正文：
   - 复用既有 `优化中...` / `翻译中...` 提示
3. 错误反馈：
   - 先复用浏览器 `console.error`
   - 若项目已有 toast 组件则接入；若没有，本轮可先不新增依赖，只保留局部文案和控制台错误

### 7. 与通知功能的关系

当前 `App.tsx` 会在优化或翻译成功时触发系统通知。

手动链路若继续沿用这套逻辑，可能导致用户点击按钮后立刻又收到“识别完成”通知，语义不准确。

设计建议：

- 通知逻辑增加触发来源判断，默认仅对自动链路发送通知。
- 手动链路完成后仅通过卡片刷新体现结果，不触发系统通知。

如果本轮不修改通知结构，则至少需要在文档中记录该风险，避免实施时遗漏。

## 测试案例

1. 按钮展示：普通已完成分段显示“手动优化与翻译”按钮。
2. 忙碌禁用：点击后按钮变为处理中，重复点击无效。
3. 状态联动：优化/翻译处理中时，按钮随状态自动禁用。
4. 失败重试：命令失败后按钮恢复可点，用户可再次触发。
5. 列表刷新：手动成功后，卡片内容更新为新的优化文本与英文翻译。
6. 通知隔离：手动触发成功后，不出现误导性的“识别完成”系统通知。
