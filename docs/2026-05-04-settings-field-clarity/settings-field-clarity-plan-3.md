# Plan 3: 校验反馈与验证方案

## 前置依赖

- Plan 1：信息架构与字段文案体系
- Plan 2：前端组件与交互改造

## 本次目标

1. 将后端已有字段约束前移到前端，减少保存后才发现错误的成本。
2. 建立字段级错误提示与保存态反馈机制。
3. 制定覆盖正常路径、边界条件和异常场景的验证清单。

## 涉及文件

- `src/src/components/SettingsModal.tsx`
- `src-tauri/src/settings.rs`
- `src-tauri/src/llm_settings.rs`

## 详细设计

### 1. 前端校验规则与后端约束对齐

根据当前 Rust 约束，前端至少同步以下规则：

1. `threshold`：`0 < value < 1`
2. `min_silence_duration`：`value >= 0`
3. `min_speech_duration`：`value >= 0`
4. `max_speech_duration`：`value > 0`
5. `num_threads`：`1 <= value <= 16`
6. `provider_url`：去除空白后不能为空
7. `optimize_prompt_template`：去除空白后不能为空
8. `translate_prompt_template`：去除空白后不能为空

前端校验只负责更早提示，不替代后端校验；保存时仍然依赖后端做最终防线。

### 2. 错误反馈形式

1. 字段失焦或保存前统一触发校验。
2. 错误信息显示在字段下方，文案直接说明原因，例如：
   - `静音阈值必须大于 0 且小于 1`
   - `线程数必须在 1 到 16 之间`
3. 保存按钮点击后，如存在多个错误，不提交请求，并将首个错误字段滚动到可见区域。

### 3. 保存反馈优化

保留当前保存中的禁用态，但进一步细化为：

1. `应用中...` 时禁用所有会造成二次提交的操作。
2. 保存成功后可考虑轻量成功提示，避免用户误以为按钮无响应。
3. 后端返回字符串错误时，优先映射到字段级；无法映射时再显示通用错误条。

### 4. 手工验证清单

围绕本问题补充以下验证：

1. 录入后所有字段标签仍可见。
2. 输入非法数值时，无需提交即可看到错误提示。
3. 清空 `provider_url` 或提示词时，保存前会被前端拦截。
4. 切换页签后再返回，字段错误状态与说明仍然一致。
5. 模型列表失败时，只影响模型选择提示，不影响其他字段保存。
6. 录音进行中触发保存时，界面能正确呈现后端拒绝信息。

### 5. 自动化测试建议

如果后续允许补充前端测试，可优先覆盖：

1. 字段元数据渲染正确性
2. 数值校验函数的边界值
3. 保存前错误汇总逻辑
4. 模型列表加载失败时的降级展示

## 测试案例

1. 输入 `threshold = 1`，应立即看到范围错误。
2. 输入 `num_threads = 0` 或 `17`，应阻止提交。
3. 清空润色提示词或翻译提示词，应显示必填错误。
4. 所有字段合法时，保存请求应正常发出。
5. 后端返回“录音中不可修改”时，界面应展示可理解的错误文案。
