# Plan 2: 前端组件与交互改造

## 前置依赖

- Plan 1：信息架构与字段文案体系

## 本次目标

1. 将设置页从“直接堆叠输入框”改造成可复用的字段面板结构。
2. 统一文本框、数值框、下拉框和文本域的交互方式与辅助信息展示。
3. 在不增加新依赖的前提下，保留当前视觉风格并提升可扫描性。

## 涉及文件

- `src/src/components/SettingsModal.tsx`
- `src/src/index.css` 或当前实际承载设置弹窗样式的样式文件

## 详细设计

### 1. 抽象字段容器组件

在 `SettingsModal` 内部或同目录下抽出轻量级展示组件，例如：

- `SettingsSection`
- `SettingsField`
- `FieldHint`
- `FieldError`

其中 `SettingsField` 统一处理：

- 标签区
- 描述区
- 控件区
- 辅助信息区
- 错误区

这样所有字段录入后的样式和语义承载方式保持一致。

### 2. 页面布局调整

当前 `grid grid-cols-2` 的裸输入布局不适合表达复杂语义，建议改成：

1. VAD、ASR 使用双列卡片式字段布局。
2. LLM 接入参数使用单列堆叠布局，避免长文本被压缩。
3. 提示词编辑区采用全宽块布局，并把说明放在文本域上方。

### 3. 可视化提示策略

建议使用以下视觉元素，但保持轻量：

- 标签：较高对比度，保证录入后仍清晰
- 描述：较浅文字，解释用途
- 辅助信息：更浅一层，可包含单位、范围、示例
- 错误态：边框与文案联动变色
- 加载态：模型列表处显示内联状态，不阻塞整页操作

### 4. 特殊字段交互

1. `api_key`
   - 默认使用密码输入框
   - 增加“显示 / 隐藏”切换，避免用户反复误读和误改
2. `selected_model`
   - 下拉框标签固定显示
   - 模型列表加载中时保留当前值并显示状态提示
   - 加载失败时展示非阻塞错误提示，不清空当前已保存值
3. `optimize_prompt_template` / `translate_prompt_template`
   - 每个文本域上方增加一句“输出协议要求”
   - 可在右上角补充“恢复默认”入口，前提是实现时先确认是否接受该交互

### 5. 保存区交互

底部按钮区增加一条静态提示：

- `保存后会重新加载识别模型，录音中不可修改`

这样能提前解释后端 `apply_settings` 的行为，减少用户对保存耗时和禁用条件的困惑。

## 测试案例

1. VAD 和 ASR 字段在桌面宽度下保持整齐双列，窄宽度下能自然换行。
2. LLM 配置中的长文本字段不出现标签与说明错位。
3. API Key 在默认状态下不会明文暴露，但用户仍可主动查看。
4. 模型列表加载、成功、失败三种状态均不会遮挡字段标签或当前值。
