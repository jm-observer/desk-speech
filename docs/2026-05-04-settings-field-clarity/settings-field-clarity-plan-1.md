# Plan 1: 信息架构与字段文案体系

## 前置依赖
无

## 本次目标

1. 为设置页建立稳定的信息层级，解决输入后字段含义消失的问题。
2. 明确每个字段的展示名称、用途说明、单位范围、示例和风险提示。
3. 为后续组件改造提供统一的数据描述来源，避免继续在 JSX 中手写零散文案。

## 涉及文件

- `src/src/components/SettingsModal.tsx`
- `src/src/api/tauri-client.ts`

## 详细设计

### 1. 建立字段元数据配置

在前端设置页附近定义一组字段元数据，例如 `fieldDefinitions`，每个字段至少包含：

- `key`：对应 `AppSettings` 字段名
- `label`：固定显示标签
- `description`：一句话用途说明
- `helpText`：单位、范围、示例或风险提示
- `inputType`：`number` / `text` / `select` / `textarea`
- `tab`：归属页签

这样可以把“字段是什么”和“字段如何展示”从 JSX 中抽离出来，避免后续新增参数时重复散落。

### 2. 按参数组补充分组说明

每个页签顶部增加一个分组说明块：

- VAD：解释与切段准确性相关
- ASR：解释与识别速度和资源占用相关
- LLM：解释与远端调用、润色和翻译相关

这个说明块要先于字段列表展示，帮助用户在阅读单字段之前建立整体上下文。

### 3. 统一标签命名规范

字段命名原则如下：

1. 界面主标签优先使用业务语义中文，不直接暴露内部键名。
2. 需要帮助技术用户时，可在次级文字中补充英文键名，如 `threshold`。
3. 单位不写进字段值里，而放在辅助信息行单独展示。

### 4. `placeholder` 职责收缩

调整后 `placeholder` 只承担“示例输入”的作用，不再承担唯一字段说明。例如：

- `静音阈值` 输入框 placeholder 可写 `例如 0.2`
- `模型服务地址` 输入框 placeholder 可写 `https://api.openai.com/v1`

### 5. 字段展示优先级

字段内容按以下优先级呈现：

1. 必须始终可见：标签、当前值控件
2. 默认可见：一句话说明、单位/范围
3. 条件可见：错误提示、加载提示、风险提示

## 测试案例

1. 任意字段在输入前后，标签始终可见且能独立识别含义。
2. 数值字段均能看到单位或范围提示，不需要依赖记忆。
3. LLM 配置区能明确区分“接入配置”和“提示词配置”。
4. 同一页签中多个字段按统一结构展示，无视觉层级混乱。
